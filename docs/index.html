Memory for coding agents.
Written by the one who did the work.

One 6 MB Rust binary, one SQLite file, no LLM, no key, no server. Claude Code, Codex, Gemini CLI, Cursor and the rest forget everything between sessions. memorycastle keeps, per repository, what was decided, what was rejected, what was measured, and the exact lines of code it lives in.

Measured against Mem0 and cognee, the two best-known open-source agent memories, each with and without a paid OpenAI key: memorycastle wins 11 of 16 rows, no competitor more than 4, with no key at all. Keyword answers in 2.5 ms from a 9 MB process. A note edited and re-indexed in place in 0.19 s. Four agent tasks on 50% fewer tokens than cognee and 61% fewer than Mem0. The only one that answers "no relevant note" when there is none, and the only one that keeps a reversed decision reversed. Where Mem0 wins, it is a bare vector store with a model a tenth the size, and we say so. The numbers.

Two lines. The second finds every agent on the machine and wires it. Restart the agents.

The loop

Four steps. Nothing invented.

The notes are the memory. Everything else is derived from them and can be rebuilt from the repository alone.

The agent writes a note

At the end of a task that changed a decision: Context, Decision, Rejected, Measured, in memorycastle/journal/, committed with the code. Written in the session that did the work, with the numbers still in hand.

The store indexes it

Split by heading, indexed for keywords with SQLite FTS5, embedded with a local EmbeddingGemma 2 model, int8, on the CPU. No API key, no network after the first download.

A question gets a paragraph and a line range

Keyword and meaning results are fused, judged for confidence, reranked by what the note declares it is about. The answer ends with path:start-end: the lines to read, not the file.

Hooks keep it honest

Recall on every prompt, the right notes before every edit, a read guard, a silent read ledger, and the note asked for at the moments it is due. In Claude Code, Codex, Gemini CLI and Cursor.

The answer

A fixed grammar, for eyes and parsers alike

A hit line with confidence and section, a title and author, label value fields, a blank line, then a lettered table of code spans to read first. By default a hit is one line and the note's Decision sentence, about 50 tokens; --sections opens the one you picked; every field typed with --json.

Memory that says "check me"

A note knows when its code changed

At save, the store hashes the body of every function the note names. At search, a note whose function has since changed is labelled and ranked under one whose code still matches. Deterministic: the hash then against the hash now. The agent is told to read those lines before trusting the paragraph.

2. ...constant-uses.md:6     0.77   Context  code changed since: is_identifier_use
Honesty

A number that can go down.

The status line shows tokens saved this session. It is not a running total. Every time it draws, it is recomputed from the ledger for the whole session:

saved = bytes the printed spans stood in for
        − bytes of those reads
        − bytes of every lookup this session printed
Falls when
A lookup leads to no read: the third term grows by its size and nothing offsets it. A guided read followed by reading the same file whole is cancelled, and counted.
Rises when
A printed span stands in for a file the agent would have read; over a working session the reads dominate and the figure climbs.
Never moves
Idle time, saving notes, hooks that print nothing. Recall and reminders are silent when they have nothing, so they cost zero then.
The point
A number that can go down is one you can believe when it goes up.
If negative
The tool is costing more than it saves and the status line says so.

One that only adds would climb forever and mean nothing.

Without being asked

The note happens at the moments it is due.

No human reminds the agent. The hooks do, from the edits ledger, not from reading the chat, so they cannot nag when nothing was edited.

When
Every prompt.
Happens
Recall: when the journal is confident about the topic, one line per note with its Decision sentence, each note once per session. Mid-session, once, when five files were edited or thirty minutes passed since the last note, then quiet for thirty minutes.
Why then
The session that would not have searched still sees the note; the one that searches sees nothing new.
When
After a commit.
Happens
One line with the files edited since the last note; the agent writes it or ignores it.
Why then
A task just closed and the facts are still in context.
When
Before compaction.
Happens
The agent is held once with the reason and a draft; the second attempt passes, so nothing can wedge.
Why then
The why is about to be summarised away.
When
At stop.
Happens
The same hold, once. If no decision was made, the agent says so and stops.
Why then
The turn is ending; after it, nobody writes the note.

A week on a large project

Mira, a payments monorepo, three agents.

A made-up team, a real tool: every command and number below is what memorycastle does today. Mira's company has one big repository with 4,000 files, nine people, and AI coding agents that forget everything when a session ends.

How it started
Mira reads about memorycastle: a memory for AI coding agents. An agent writes down what it decided and why at the end of each task, and the next agent, on any machine, finds that note before it repeats the work. Fewer wrong turns, fewer tokens. What convinces her: it is one small Rust program, it uses Google's EmbeddingGemma 2 model to understand meaning, it runs fully offline once installed, it needs no account and no API key, and it uses a fraction of the memory of the alternatives. She tries it on her own laptop:
curl -fsSL https://raw.githubusercontent.com/abhksinha/MemoryCastle/main/scripts/get.sh | sh
memcastle install
The second command finds Claude Code, Codex and Cursor on her machine and connects each one. Inside the company repository it reads the 4,000 files and learns where every function is, in four seconds. It also reads her last month of agent chat logs, so the savings counter starts with a history instead of zero. There are no notes yet; her status line says 0 notes.
Monday afternoon
Mira asks Claude to move "settlement retries" from a timed job to a queue. Forty minutes in, five files have changed, and memorycastle quietly tells Claude it owes a note. Claude writes it in the repository: the queue was chosen because retries must survive a deploy; a Redis stream was tried and dropped because it could not keep one customer's events in order; the slow-request number before and after. The note is a plain Markdown file. It is committed with the code, like any other file.
Tuesday
Dev, a teammate, pulls the repository and opens Codex. He asks it to "make settlement retries faster by batching". Before Codex answers, memorycastle shows it one line: Mira's note, with the sentence about the Redis stream that was rejected. Codex reads the forty lines of code the note points to and proposes batching inside the queue instead of adding a second stream. Nobody told Codex about Monday. The note did.
Wednesday
Priya edits a 2,400-line file that eleven notes mention. As her agent starts the edit, memorycastle finds the one function she is changing and shows only the two notes about that function, with the 180 lines it lives in. Her agent reads those, not the whole file. When it tries to read the whole file anyway, memorycastle stops it once and gives it the exact lines to read instead. Her status line that evening: ~41k (58%) this session, tokens not spent.
Thursday
Someone rewrites that same function. The next time a search returns Priya's note, it is marked code changed since: post_batch and ranked below notes whose code is still the same. Her agent reads the new code before trusting the old note, finds the rule still holds, and writes a one-line note saying it checked. Mira's note about retries is untouched, because its code did not change.
Friday
A long session runs out of room, and the agent is about to compress its own memory of the conversation. memorycastle holds it once and asks for the note first, with a draft already filled in from the files it edited. The agent writes the decision and the numbers while it still remembers them, saves, and carries on. The status line shows the week: ~310k (66%) last 7 sessions. On Friday that number fell by 3k while an agent searched four times for something nobody had written down. The team sees that too, and someone writes the missing note.

What never happened that week: nobody set up a server, pasted a key, uploaded a chat log, or explained a graph. Nine people pulled a folder of Markdown files, and their agents stopped making the same decision twice. On each laptop the memory is one file under ~/.local/share/, rebuilt from the repository if it is ever deleted.

Terms

The words on this page.

Short definitions of every term the tables use, in the order you meet them.

Note
One Markdown file in memorycastle/journal/, written by an agent or a person at the end of a task: a title, author and date, the files it is about, and sections for Context, Decision, Rejected, Measured and Open. The notes are the memory; everything else is derived from them.
Journal
All the notes of one repository. "Project 1, 48 notes" is a journal of 48 files.
Chunk
A piece of a note the index works on: one section, split further at about 200 words. A hit points at a chunk and prints its line number.
Keyword search
BM25 over the chunks through SQLite FTS5. No model is loaded; under 3 ms from a 9 MB process. Used alone when an identifier from the question is found verbatim.
Meaning search
The question and every chunk as vectors from a local embedding model (EmbeddingGemma 2, 300M parameters, int8); ranked by cosine similarity, fused with BM25. 52 ms warm, 300 MB while the model is loaded.
Confidence
A number from 0 to 1 printed on every hit: the model's cosine rescaled between a floor and a ceiling set on a gold set, reduced when the question's rare words are absent from the chunk. Under 0.30 the hit is dropped and the answer is "no relevant note". An identifier found verbatim is 1.0.
Gold set
A private list of real questions about a journal with the note that answers each, plus questions whose right answer is nothing. Every retrieval number on this page is scored against one.
recall@3
The share of questions whose right note is among the first three hits. 0.97 means 55 of 57. recall@10: the same within the first ten.
MRR
Mean reciprocal rank: 1 when the right note is first, 1/2 when second, 1/3 when third, averaged over the questions. 0.85 means the right note is usually first and sometimes second. A difference of 0.01 on 30 questions is one note moving by one rank.
Absent topic
A question about something no note covers. The right answer is nothing; a system that returns its nearest chunk anyway is counted as answering. 11 per journal here.
Superseded note
A note replaced by a later one, declared by the newer note's Supersedes: line. It is kept, labelled and ranked below its replacement, never edited or deleted.
Read spans
The path:start-end lines after every answer: the definitions the question or the top notes name, re-found by their anchor line if the file has changed since indexing. The agent reads those lines, not the file.
Ingest
Building the index from the notes: hash, split, FTS5, one embedding per chunk. Re-index: the same for one edited note, with unchanged chunks carried over.
Raw, with key
Mem0 raw is Mem0 with extraction off, a local 33M embedder over the same chunks, no key. "With key" is Mem0 or cognee in their intended mode, an OpenAI model extracting and embedding, paid per token.
Tokens, uncached
What an agent run cost: total tokens the model processed, of which uncached input is the part not served from the prompt cache. Retrieval bytes: the bytes the memory tool itself returned to the agent.
Resident MB
Memory the answering process holds while it answers, measured as peak resident set size.
Pre-registered
The questions, tasks and pass criteria were written down before any competitor number was seen; later setup fixes are logged with a time.
Comparison

Lighter, honest, and it knows when to say nothing.

Rust, one binary, one file. No Python runtime, no vector database, no graph database, no API key, no network. Every answer in milliseconds from a process a hundred times smaller than an LLM memory stack, and the retrieval is equal or better on real journals.

Mem0 is the most widely adopted open-source agent memory, a vector store with LLM extraction and an API; its graph features are a paid tier. cognee is the best-known open-source graph memory for agents. Both are measured below, each without a key and with one. Both solve a broader problem than this one: Mem0 remembers what users and agents say across conversations, with an LLM deciding what to keep and what to update; cognee turns any documents, conversations and code into a knowledge graph plus vectors, with a server, a UI and a cloud. memorycastle solves one narrow problem, a coding team's decisions per repository, and the narrowness is where the architecture differs.

Why each winner matters.

Each line is the row, what it means in a working session, and what losing it costs.

Row
Absent topic: nothing when there is nothing.
Means
An agent asks memory about things nobody wrote down several times a session. "No relevant note" removes that work, and it is deterministic: the same question gives the same nothing.
Losing it
Mem0 and cognee return the nearest chunk every time, scored, with no usable floor; the agent weighs it and often acts on it.
Row
Superseded note: the reversed decision stays reversed.
Means
The label and the rank come from a declared Supersedes: line, so they cannot be wrong.
Losing it
A memory that serves the reversed decision first is worse than none: the agent rebuilds what the team undid. Mem0 and cognee order the pair by similarity, a coin toss.
Row
Ranking: within one rank swap, all three journals.
Means
Every system finds the right note in the top three; rank 1 against rank 2 is one section read instead of two.
Losing it
One extra line read. Sessions are won on the other rows, which is why the floor was kept over a few points of rank.
Row
One note edited: 0.19 s, in place.
Means
save runs in a hook unnoticed and replaces what was there, so memory is current after every task.
Losing it
Mem0 raw is as fast but keeps the old copies, so a daily-edited journal fills with stale duplicates; the LLM modes need seconds to minutes and a provider, so memory goes stale between batches.
Row
Answering process: 9 MB keyword, 300 MB meaning.
Means
A hook can run before every edit, and the meaning model sits beside an IDE and a build, released after five idle minutes.
Losing it
Mem0 has no keyword path, every answer loads a model; 750 MB per answering process does not fit beside a build.
Row
Retrieval bytes: 92 KB across four tasks.
Means
The part of a session the memory controls: what the agent reads to find the fact. One line and the Decision sentence per hit, then the spans.
Losing it
194 KB and 376 KB for the same four correct answers, and 50% to 61% more tokens across the run.
Row
Where Mem0 wins: ingest and warm query speed.
Means
Bare vectors over raw chunks with a 33M model: 2.9 s for ten notes, 5 ms a query. That is Mem0 as a vector store, not as a memory.
Losing it
Its extraction, dedupe and updates need the LLM mode: 685 s and a million tokens for ten notes, and a lower rank than memorycastle on all three journals.

What the comparison changed in memorycastle.

Each line is one thing the run showed, what changed because of it, and what the change measured.

Saw
Mem0 serves one sentence per memory and its agent read 4 KB where ours read 15 KB. The label log said the same from the other side: 22 notes served, 1 opened.
Changed
A hit is one line and the note's first Decision sentence, about 50 tokens; --sections opens the one the agent picked.
Measured
Four tasks: 92 KB of retrieval, 700k tokens, half of what the longer answer cost; every rubric passed.
Saw
Three absent questions still got an answer at 0.50. Confidence was the larger of the model's cosine and the share of question words present, so "state", "library", "pick" carried a chunk the model had put under the floor.
Changed
Words can add to the model's verdict, never overrule it: coverage is capped at the model's own cosine, and the fused score is scaled by it.
Measured
Absent answers 3, 0, 4 of 11 to 0, 0, 2; recall@3 on the largest journal 0.905 to 0.968, because false hits had been filling the top ten; one rank swap lost on the middle one.
Saw
Mem0's speed rows come from a 33M-parameter embedder, a tenth of ours.
Tried
Its vectors injected into memorycastle's own stores and scored through the same fusion, with and without bge's query instruction.
Measured
MRR 0.742 against 0.838 on the largest journal, below on all three; it loses the paraphrase questions. The 300M model stays.
Saw
Ten warm embedding servers resident during the agent runs: a server exiting on idle removed a socket that by then belonged to a newer one.
Changed
The server claims the socket before loading the model, stands down if another answers, and removes the file only if it still owns it.
Measured
One server per machine, 66 MB after five idle minutes.
Saw
Mem0's search has a threshold, default 0.1, which nothing falls under.
Tried
The threshold set at the lowest score any right answer received, so recall is untouched.
Measured
Still 1 to 2 of 11 absent questions answered on the small journals and 11 of 11 on the largest, where a right answer scored 0.335; with a key, 0, 5 and 7 of 11. The scores do not separate "nothing on this" from "phrased differently"; a floor has to be calibrated.

The rule behind every trade here: silence over noise. A rank error costs an agent one extra line; a confident wrong note costs it a wrong decision. So the floor stays, supersession is declared rather than inferred, recall prints nothing under 0.50, and the words of a question cannot lift a chunk the model put under the floor. Each of those rules gives up a little rank on wording-heavy questions and buys silence on absent ones; the few hundredths of MRR that Mem0's bare vector mode takes on two small journals are that price, and we pay it on purpose. The last rule was found by reading the absent questions memorycastle still answered: on the current stores it took them from 3, 0 and 4 of 11 to 0, 0 and 2, and recall@3 on the largest journal rose from 0.905 to 0.968 because the false hits had been filling the top ten.

The trade is explicit. cognee can remember a support transcript or a PDF and answer questions a human never wrote down; memorycastle cannot, because nothing is extracted, only what an agent chose to write is stored. In exchange, a memorycastle answer is always traceable to a sentence a person or agent wrote, costs under a second and a few hundred MB at most, and the graph cannot hallucinate an edge. For a coding team that wants its agents to stop repeating rejected experiments, that trade is the right one. For a company that wants memory over everything it has, it is not.

Design

Why smaller is also better, for this job.

Each line is what the larger designs do, what memorycastle does instead, and what that is worth.

They
Read the transcript later and extract what happened, guessing where it is silent.
We
The agent that made the change writes the note in that session, with the rejected approach and the measured number still in hand.
Worth
The why was never in the code; only the one who decided can write it, and it costs one note instead of a model pass forever.
They
A model proposes the graph: entities and relations, including edges nobody wrote.
We
Edges are the file names and symbols a note names in backticks, plus a line scan of the checkout.
Worth
Nothing is invented. A wrong edge is a typo in a note, and git blame finds who wrote it.
They
Ingest is one or more LLM calls per chunk: a million tokens for ten notes, minutes per journal.
We
Saving a note is a hash check, a heading split, FTS5, and one local embedding per chunk at 0.2 s.
Worth
Ten notes in 21 s, an edited note in 0.19 s, no key, no bill, so it runs in a hook on every save.
They
Answer with a subgraph, a list of memories, or generated prose.
We
Which paragraph to trust and which 40 lines to read: ranked path:start-end spans, re-anchored when the file has changed.
Worth
92 KB of retrieval across four agent tasks against 194 KB and 376 KB, for the same four correct answers.
They
A store to back up, a server to keep in sync, or a cloud account, and a team sharing by access.
We
Delete the SQLite file and install rebuilds it from the notes in the repo, identically.
Worth
Reproducible from git alone; teammates share memory by pulling.
They
Return the nearest chunk to any question, scored, with no usable floor: 11 of 11 absent questions answered.
We
Confidence calibrated on a gold set, a near-miss gate on the question's rare words, and the model's verdict that words cannot overrule.
Worth
"No relevant note" is a real answer: 0, 0 and 2 of 11. An agent is never steered by a plausible neighbour.

None of this makes memorycastle a replacement for Mem0 or cognee. It makes it the right size for one job: a repository, its agents, and the decisions they should not have to make twice. The resource gap is not an optimisation of the same design; it falls out of not extracting, not inferring and not serving.

Scope

One repo, one memory.

Every call works out the project from the current directory: the git root, and the remote normalised to host/owner/repo. A fresh clone on another machine is the same project; a worktree is the same as its main checkout. Each query binds that project before ranking, so a search in one repo can never return another repo's note.

Case
Sister repos.
Rule
Declare a group once per repo with memcastle project group <name>; then search --related includes the siblings, labelled and down-weighted so the home repo wins ties.
Why
Without a group, --related searches nothing and says how to declare one. Isolation stays the gate.
Case
Repos without a remote.
Rule
The project is keyed by the directory path, so moving the directory starts a new project. Add a remote and it binds to that instead.
Why
With a remote, a move or a second clone changes nothing.
Case
Teammates.
Rule
They get the notes by pulling the repo. Their first memcastle install on a machine wires the agents; inside the repo it indexes the notes.
Why
No server, no account, no sync.
Case
What is never searched.
Rule
There is no "everything I know". A question about another repo is answered in that repo or through a declared group.
Why
The isolation is a test in the suite, not a setting.
Install

Start.

curl -fsSL https://raw.githubusercontent.com/abhksinha/MemoryCastle/main/scripts/get.sh | sh
memcastle install                 # every agent on this machine, from any directory
cd your-repo && memcastle install # also this repo: journal, code index, past transcripts
memcastle search "why did we pick int8"
memcastle links src/store.rs
memcastle guide                   # the instructions an agent follows
memcastle uninstall --purge       # the reverse, notes stay

Prerequisites: macOS Apple silicon or Linux x86_64 (prebuilt), otherwise Rust 1.85 and cargo. The embedding model is EmbeddingGemma 2, downloaded once with a pinned checksum. Everything lands under ~/.local/. Codex asks you to trust the hooks once with /hooks.
