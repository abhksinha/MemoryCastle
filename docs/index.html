Shared memory for coding agents.
One binary, one SQLite file, no LLM.

Claude Code, Codex, Gemini CLI, Antigravity, Cursor, GitHub Copilot and OpenCode forget everything between sessions. memorycastle gives them one memory per repository: what was decided, what was tried and rejected, what was measured, and the exact lines of code it lives in.

curl -fsSL https://raw.githubusercontent.com/abhksinha/MemoryCastle/main/scripts/get.sh | sh
memcastle install

Two lines. The second finds every agent on the machine and wires it. Restart the agents.

How it works

Agents write notes

At the end of a task that changed a decision, the agent writes a short Markdown note in memorycastle/journal/: Context, Decision, Rejected, Measured. The notes are committed with the code. They are the memory; everything else is derived.

Notes are indexed locally

Each note is split by heading, indexed for keywords (SQLite FTS5) and embedded with a local EmbeddingGemma 2 model, int8, on the CPU. No API key, no network after the first download.

A question gets a paragraph and a line range

Keyword and meaning results are fused, judged for confidence, and reranked by what the note declares it is about. The answer ends with read: path:start-end, the exact lines to open.

Hooks keep it honest

In Claude Code, a lookup runs before every edit, reads are logged, and the savings counter shows what the printed spans stood in for. A note is drafted when a session changes code and saves none, and the agent is asked at the three moments a note is due: before compaction, after a commit, at stop.

Every number above was measured on an M5 MacBook Air with a release build and is reproduced in the repository's BENCHMARKS.md. The engineering rule behind them: do less, allocate less, move less, measure.

Compared with cognee

cognee is the best-known open-source memory engine for agents. It solves a broader problem: any documents, conversations and code, for any agent, turned into a knowledge graph plus vectors, with a server, a UI and a cloud. memorycastle solves one narrow problem, a coding team's decisions per repository, and the narrowness is where the architecture differs.

The trade is explicit. cognee can remember a support transcript or a PDF and answer questions a human never wrote down; memorycastle cannot, because nothing is extracted, only what an agent chose to write is stored. In exchange, a memorycastle answer is always traceable to a sentence a person or agent wrote, costs under a second and a few hundred MB at most, and the "graph" cannot hallucinate an edge. For a coding team that wants its agents to stop repeating rejected experiments, that trade is the right one. For a company that wants memory over everything it has, it is not.

Why smaller is also better, for this job

Nothing is invented

cognee's graph is proposed by a model, so an edge can be wrong and nobody wrote it. memorycastle's edges are the file names and symbols a note names in backticks. A wrong edge is a typo in a note, and git blame finds who wrote it.

Ingest costs no tokens

A cognify run sends every chunk through an extraction model. Saving a note here is a hash check, a heading split, FTS5, and one local embedding per chunk at 0.28 s on a laptop CPU. A 90-chunk journal indexes in 21 s with no API bill.

The answer is a place in the code

A coding agent does not want a subgraph; it wants which paragraph to trust and which 40 lines to read. Every answer ends with ranked path:start-end spans, re-anchored when the file has changed since indexing.

Reproducible from git alone

Delete the SQLite file and install rebuilds it from the notes in the repo, identically. No store to back up, no server to keep in sync, no cloud account. Teammates share memory by pulling.

Offline, and it stays small

After the one model download it never opens a network connection. The store grows at about 2.5 MB of text and 3.5 MB of vectors per 700 notes; search over them is 3 ms and the whole process stays under 300 MB.

It knows when it does not know

Confidence is calibrated on a gold set; below the floor the answer is "no relevant note" rather than the nearest wrong one. A note about the same file but a different topic is dropped by a near-miss gate, so an agent is never steered by a plausible neighbour.

None of this makes memorycastle a replacement for cognee. It makes it the right size for one job: a repository, its agents, and the decisions they should not have to make twice. The resource gap is not an optimisation of the same design; it falls out of not extracting, not inferring and not serving.

Start

curl -fsSL https://raw.githubusercontent.com/abhksinha/MemoryCastle/main/scripts/get.sh | sh
memcastle install                 # every agent on this machine, from any directory
cd your-repo && memcastle install # also this repo: journal, code index, past transcripts
memcastle search "why did we pick int8"
memcastle links src/store.rs
memcastle uninstall --purge       # the reverse, notes stay

Prerequisites: macOS Apple silicon or Linux x86_64 (prebuilt), otherwise Rust 1.80 and cargo. The embedding model is EmbeddingGemma 2, downloaded once with a pinned checksum. Everything lands under ~/.local/.
