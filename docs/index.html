Memory for coding agents.
Written by the one who did the work.

One binary, one SQLite file, no LLM. Claude Code, Codex, Gemini CLI, Cursor and the rest forget everything between sessions. memorycastle keeps, per repository, what was decided, what was rejected, what was measured, and the exact lines of code it lives in.

curl -fsSL https://raw.githubusercontent.com/abhksinha/MemoryCastle/main/scripts/get.sh | sh
memcastle install

Two lines. The second finds every agent on the machine and wires it. Restart the agents.

The loop

Four steps. Nothing invented.

The notes are the memory. Everything else is derived from them and can be rebuilt from the repository alone.

The agent writes a note

At the end of a task that changed a decision: Context, Decision, Rejected, Measured, in memorycastle/journal/, committed with the code. Written in the session that did the work, with the numbers still in hand.

The store indexes it

Split by heading, indexed for keywords with SQLite FTS5, embedded with a local EmbeddingGemma 2 model, int8, on the CPU. No API key, no network after the first download.

A question gets a paragraph and a line range

Keyword and meaning results are fused, judged for confidence, reranked by what the note declares it is about. The answer ends with path:start-end: the lines to read, not the file.

Hooks keep it honest

Recall on every prompt, the right notes before every edit, a read guard, a silent read ledger, and the note asked for at the moments it is due. In Claude Code, Codex, Gemini CLI and Cursor.

The answer

A fixed grammar, for eyes and parsers alike

A hit line with confidence and section, a title and author, label value fields, a blank line, then a lettered table of code spans to read first. Fifteen tokens per hit with --brief; every field typed with --json.

Memory that says "check me"

A note knows when its code changed

At save, the store hashes the body of every function the note names. At search, a note whose function has since changed is labelled and ranked under one whose code still matches. Deterministic: the hash then against the hash now. The agent is told to read those lines before trusting the paragraph.

1. ...honest-savings.md:71   0.82   Open
2. ...constant-uses.md:6     0.77   Context  code changed since: is_identifier_use
Honesty

A number that can go down.

The status line shows tokens saved this session. It is not a running total. Every time it draws, it is recomputed from the ledger for the whole session:

saved = bytes the printed spans stood in for
        − bytes of those reads
        − bytes of every lookup this session printed

Why it falls

The first two terms only grow. The third grows with every search, links call and recall line, guided or not. A lookup that leads to no read is a cost with no saving, so the net drops by its size. A guided read followed by reading the same file whole is cancelled, and counted.

Why that is the point

A number that can go down is one you can believe when it goes up. If the net turns negative, the tool is costing more than it saves and the status line says so. A counter that only adds would climb forever and mean nothing.

What never moves it

Idle time, saving notes, hooks that print nothing. Recall and reminders are silent when they have nothing, so they cost zero then. Over a working session the reads dominate and the figure climbs.

Without being asked

The note happens at the moments it is due.

No human reminds the agent. The hooks do, from the edits ledger, not from reading the chat, so they cannot nag when nothing was edited.

Every prompt

Recall: when the journal is confident about the topic, one line per note, each note once per session. And once mid-session, when five files were edited or thirty minutes passed since the last note, then quiet for thirty minutes.

After a commit

A task just closed. One line with the files edited since the last note; the agent writes it or ignores it.

Before compaction

The why is about to be summarised away. The agent is held once with the reason and a draft; the second attempt passes, so nothing can wedge.

At stop

The same hold, once. If no decision was made, the agent says so and stops.

Claude Code through its plugin; Codex, Gemini CLI and Cursor through memcastle hook, wired by install. Copilot, OpenCode and Antigravity have no hook surface and get the instructions and the tools.

A week on a large project

Mira, a payments monorepo, three agents.

Hypothetical, but every command and number is what the tool does today. The repo has 4,000 files, a team of nine, and agents that until now started every session from zero.

Monday: install

Mira runs the two lines on her laptop. install finds Claude Code, Codex and Cursor, wires each, and in the repo builds the code index: 4,000 files, 60,000 definitions, four seconds. Her last month of Claude and Codex transcripts go into the ledger so the savings counter has a past. The journal is empty; the status line says 0 notes.

Monday afternoon: the first note

She asks Claude to move settlement retries from a cron job to a queue. Forty minutes in, the fifth file is edited and the prompt hook says a note is owed. Claude writes it: queue chosen over cron because retries must survive a deploy; a Redis stream was tried and rejected for lacking per-tenant ordering; p95 retry latency before and after. save fills the author and date, embeds four chunks in a second, and the note is committed with the code.

Tuesday: a teammate's agent

Dev pulls, opens Codex, and asks it to "make settlement retries faster by batching". Before Codex answers, the recall hook prints one line: Mira's note, 0.74, section Rejected. Codex opens the section, reads the forty lines the note points to in settlement/retry.rs, and proposes batching inside the queue consumer instead of a second stream. No one told it about Monday.

Wednesday: the edit hook

Priya edits ledger/post.rs, a 2,400-line file with eleven notes about it. The hook finds the function her edit sits in, post_batch, and prints the two notes that name it, with its span, 180 lines. She reads those, not the file. The read guard blocks her agent's one attempt to read the whole file, once, with the range to read instead. Status line that evening: ~41k (58%) this session.

Thursday: the code moves on

A refactor rewrites post_batch. The next search that returns Priya's note shows code changed since: post_batch and ranks it under a note whose code still matches. Her agent reads the new function before trusting the paragraph, finds the invariant still holds, and writes a one-line note that supersedes nothing but records that it checked. Mira's week-old note on retries is untouched; its function did not change.

Friday: compaction and the number

A long session hits the context limit mid-task. The hook holds compaction once with the reason and a draft; the agent fills Decision and Measured from facts still in context, saves, and compaction proceeds. The status line shows the week: ~310k (66%) last 7 sessions. On Friday it fell by 3k while an agent searched four times for something nobody had written down. The team can see that too, and someone writes the note.

What never happened: a server was stood up, a key was pasted, a transcript was uploaded, a graph was explained. The nine people pulled a directory of Markdown and their agents stopped making the same decision twice. The store on each laptop is one file under ~/.local/share/, rebuilt from the repo if deleted.

Comparison

Compared with cognee.

cognee is the best-known open-source memory engine for agents. It solves a broader problem: any documents, conversations and code, for any agent, turned into a knowledge graph plus vectors, with a server, a UI and a cloud. memorycastle solves one narrow problem, a coding team's decisions per repository, and the narrowness is where the architecture differs.

Why each winner matters.

Nothing, when there is nothing

An agent asks memory about things nobody wrote down several times a session. cognee returns the nearest chunk every time, scored, with no floor, and the agent weighs it and often acts on it. "No relevant note" is the answer that removes work, and it is deterministic: the same question gives the same nothing, not a different plausible neighbour per run.

The reversed decision stays reversed

A memory that serves the superseded note first, unlabelled, is worse than no memory: the agent rebuilds what the team undid. The label and the rank come from a declared Supersedes: line, so they cannot be wrong.

The lead grows with the journal

Behind by 0.01 at 10 notes, ahead by 0.01 at 22 and by 0.06 at 40, against the paid configuration. A journal grows every day; the number that matters is the one at 40 notes and beyond. Rank 1 against rank 2 is one section read instead of two.

Save in a hook, not a batch

A note is written at the end of every task. 0.19 s means save runs in a hook unnoticed; 13 s and 3 GB means batches, and memory stale between them. Zero tokens means no bill, no key, no network.

Small enough to run before every edit

9 MB for a keyword answer is what lets a hook run before each edit. 300 MB for a meaning answer, released after five idle minutes, sits beside an IDE and a build; 750 MB per answering process does not.

Half the context spent on memory

Retrieval bytes are the part the memory controls. Half of cognee's for the same four correct answers is half the context kept for the task, and 38% fewer tokens across the run.

The trade is explicit. cognee can remember a support transcript or a PDF and answer questions a human never wrote down; memorycastle cannot, because nothing is extracted, only what an agent chose to write is stored. In exchange, a memorycastle answer is always traceable to a sentence a person or agent wrote, costs under a second and a few hundred MB at most, and the graph cannot hallucinate an edge. For a coding team that wants its agents to stop repeating rejected experiments, that trade is the right one. For a company that wants memory over everything it has, it is not.

Design

Why smaller is also better, for this job.

Written by the one who did the work

The note is written by the agent that made the change, in that session, with the rejected approach and the measured number still in hand. An extractor reading the transcript later reconstructs what the author already knew, and guesses where the transcript is silent. The why was never in the code; only the one who decided can write it.

Nothing is invented

A model-proposed graph can hold an edge nobody wrote. memorycastle's edges are the file names and symbols a note names in backticks. A wrong edge is a typo in a note, and git blame finds who wrote it.

Ingest costs no tokens

Saving a note is a hash check, a heading split, FTS5, and one local embedding per chunk at 0.28 s on a laptop CPU. A 90-chunk journal indexes in 21 s with no API bill.

The answer is a place in the code

A coding agent does not want a subgraph; it wants which paragraph to trust and which 40 lines to read. Every answer ends with ranked path:start-end spans, re-anchored when the file has changed since indexing.

Reproducible from git alone

Delete the SQLite file and install rebuilds it from the notes in the repo, identically. No store to back up, no server to keep in sync, no cloud account. Teammates share memory by pulling.

It knows when it does not know

Confidence is calibrated on a gold set; below the floor the answer is "no relevant note" rather than the nearest wrong one. A note about the same file but a different topic is dropped by a near-miss gate, so an agent is never steered by a plausible neighbour.

None of this makes memorycastle a replacement for cognee. It makes it the right size for one job: a repository, its agents, and the decisions they should not have to make twice. The resource gap is not an optimisation of the same design; it falls out of not extracting, not inferring and not serving.

Scope

One repo, one memory.

Every call works out the project from the current directory: the git root, and the remote normalised to host/owner/repo. A fresh clone on another machine is the same project; a worktree is the same as its main checkout. Each query binds that project before ranking, so a search in one repo can never return another repo's note.

Sister repos

Declare a group once per repo with memcastle project group <name>; then search --related includes the siblings, labelled and down-weighted so the home repo wins ties. Without a group, --related searches nothing and says how to declare one.

Repos without a remote

The project is keyed by the directory path, so moving the directory starts a new project. Add a remote and it binds to that instead; with a remote, a move changes nothing.

Teammates

They get the notes by pulling the repo. Their first memcastle install on a machine wires the agents; inside the repo it indexes the notes. No server, no account, no sync.

What is never searched

There is no "everything I know". A question about another repo is answered in that repo or through a declared group. The isolation is a test in the suite, not a setting.

Install

Start.

curl -fsSL https://raw.githubusercontent.com/abhksinha/MemoryCastle/main/scripts/get.sh | sh
memcastle install                 # every agent on this machine, from any directory
cd your-repo && memcastle install # also this repo: journal, code index, past transcripts
memcastle search "why did we pick int8"
memcastle links src/store.rs
memcastle guide                   # the instructions an agent follows
memcastle uninstall --purge       # the reverse, notes stay

Prerequisites: macOS Apple silicon or Linux x86_64 (prebuilt), otherwise Rust 1.85 and cargo. The embedding model is EmbeddingGemma 2, downloaded once with a pinned checksum. Everything lands under ~/.local/. Codex asks you to trust the hooks once with /hooks.
